# Ripple interface

The main task is following a decision across working systems. The interface uses a compact change ledger and a map of the actual route through Switch. The original oversized introduction and rounded dashboard cards were replaced by a working review surface.

## Research

- Recent: https://recent.design/ - browse design, interface work, and product screenshots. Godly currently redirects here.
- Curated: https://curated.design/ - inspect varied web and product directions. Reviewed entries included Planes, Inflight, and Bridge. These are references for comparison, not copied templates.
- Are.na: https://www.are.na/ - explicit content structure, restrained framing, and keeping the material central.
- Linear: https://linear.app/ - compact work context and visible activity tied to an actual issue.

## Direction

Warm paper, charcoal text, and a restrained orange accent. Serif change titles sit beside monospaced record metadata. Fine rules and a dotted working map separate the route from file review. The design needs no downloaded font, image asset, or decorative illustration.

The map is functional: selecting an agent opens its proposed files. Selecting Switch opens connection details. Node states derive from actual dispatch and workspace records. There are no animated pretend replies or fabricated online indicators.

## Interaction

- New changes open in a focused dialog. Existing work stays visible in the ledger.
- Creating a change saves it. The next-step panel states whether Switch still needs connection or the request is ready to send.
- Send to Switch records a real transport receipt. Waiting for agents is a distinct state.
- Manual handoff shows the full message, supports copy, and provides selected text if clipboard access is denied.
- File review shows actual before and after content. Approval applies to the checked bundle.
- History selection, filtering, workspace views, and receipt downloads operate on persisted records.
- N creates a change. Number keys 1-4 switch views. Escape closes a dialog.
- At narrow widths the ledger rail collapses into the header. The route and working views remain available.

Verification is recorded separately in VERIFICATION.md. A design reference is not evidence that the implemented interface was rendered successfully.
